# 开放世界扩展设计 / Milestone 1

本文件描述当前 Unity 6000.6.0f1 实现；占位几何、折叠风帆和命名为原创，不引入其他游戏的资源或专有内容。原有据点制作、建造、采集、营地战斗与升级链保留。

## 1. Player Traversal

`PlayerMotor` 保留输入、近战命中窗口、闪避、受伤/死亡；`PlayerTraversal` 负责 CharacterController 位移、体力和攀爬/滑翔。输入读取一次后传入 `Simulate`，测试可直接驱动同一入口，不依赖键盘注入。

WASD 相对镜头移动；左 Alt 步行、默认跑步、左 Shift 冲刺。加速、减速、空中控制、转向、重力、跳高、终端速度、坡面角度、台阶高度、coyote time、跳跃缓冲均在 GameBalance。模拟按最大 0.025 秒分步，每次 CharacterController 位移不大于 0.18 米；落地沿可行走坡面投影速度，负垂直速度用于贴地。头顶碰撞取消上升速度。空中关闭 stepOffset。

## 2. State transitions

战斗状态 `Move / Attack / Dodge / Hurt / Dead` 与位移状态 `Grounded / Jump / Fall / Sprint / Climb / LedgeTransition / Glide` 分工明确；`CanAct`、`CanTraverse`、`BlocksCombat` 是集中入口，不允许互相绕过。

| 当前状态 | 允许与打断 |
| --- | --- |
| Grounded / Sprint | 跳跃、攻击、闪避；C 检测抓墙 |
| Jump / Fall | 空中控制、C 抓墙、G 滑翔；保留原空中攻击/闪避行为 |
| Attack / Dodge / Hurt | 不接受跳跃、攀爬、滑翔；重力和碰撞仍生效 |
| Climb | 禁止攻击/闪避；WASD 沿墙移动，顶部合法则翻越，C/X 松开 |
| LedgeTransition | 升起至顶部，再向平台内移动；碰撞/超时失败掉落 |
| Glide | 禁止攻击/闪避，G/X 取消；落地回 Grounded |
| 受伤 | 攀爬/滑翔中先脱离再进入 Hurt；致死进入 Dead |
| Dead | 禁止动作和交互，计时重生并保留物品/进度 |
| 菜单打开 | 冻结模拟、体力、战斗与交互；仅地图传送等明确菜单操作可执行 |

Animator 参数为 Speed、Action、Traversal、VerticalVelocity、Grounded、Climbing、Gliding、Attack、Dodge、Dead；翻越、攀爬、滑翔有程序生成的占位姿态，风帆只在滑翔时显示。攻击命中时机继续由 GameBalance 控制，不依赖动画长度。

## 3. Stamina

纯 C# `Stamina` 实现耗尽、夹紧、恢复延迟及跨帧剩余恢复时间。默认上限 100，冲刺每秒 16，上攀 15、横攀 10、下攀 5、静止抓附 3，滑翔 7；停止消耗 1.1 秒后每秒恢复 25。

耗尽后冲刺自动退出，须松开冲刺键并恢复至 15 后重启；攀爬/滑翔掉落且有短暂重新抓附冷却。启动攀爬/滑翔要求至少 15 体力。读档、重生和安全传送恢复体力；不把临时资源或空中动作写入存档，避免重载后被困在不可控制状态。

## 4. Climbing detection / Ledge

`climbMask` 加显式 `ClimbSurface.Climbable` 的双条件控制可攀爬面。没有组件等价于 NonClimbable；碰撞体高度和法线也必须通过阈值。仅台地和峡谷两岸几何主动添加标记。

胸口射线检测墙面，保持半径加间隙的距离，实际位移始终由 CharacterController 碰撞处理。横向移动允许扇形补探和配置范围内的法线变化；锐角、悬挑、缺失墙面会安全掉落，不做绕任意复杂网格的自动粘附。

墙面探测丢失且向上时，从前上方探测可站立顶部；检查目标胶囊及竖直抬升点空间后进入 LedgeTransition。先向上，再向前，逐步移动；禁止直接 teleport 穿越碰撞体。顶部目标深入平台，避免只站在边缘。头顶阻挡和超时退出，不做完整 IK。

## 5. Gliding

G 在离地足够高且可行动时展开折叠风帆；相对镜头方向转向，没有方向输入时继续向角色前方飞行。使用独立前进速度、转向加速度、重力倍率、垂直下降速度及消耗配置。CharacterController 仍处理碰撞；落地自动收起，受伤、耗尽或取消切到掉落。

Cinemachine 保留原虚拟相机结构；增加平滑冲刺 FOV、滑翔距离、攀爬焦点高度。碰撞使用球形扫掠并立即缩短距离，不增加震屏。

## 6. POI model / rewards / puzzle

`ExplorationWorld` 单次创建布局并注册 POI；`StableRegistry` 对空/重复 ID 抛错，不静默覆盖。`ExplorationPoi` 包含 ID、名字、类型、位置、半径和传送落点；discovered/completed 从 GameState 读取，不复制第二份运行时真相。

支持 Landmark、TeleportPoint、Treasure、EnemyCamp、ResourceArea、Puzzle、Secret，共 9 个点。物理触发发现 → 通知 → 存档 → 地图标记；不是每个 POI 每帧检查距离。

`WorldInteractable` 扩展接入信标、行旅匣、共鸣石，保留原交互距离和视线验证。新宝箱分 Common / Rare，默认矿石 2 / 矿石 6 + 药剂 2，由 GameBalance 配置；事务成功后才标记 opened。旧宝箱仍使用 `claimed`，不重复发奖。

纯规则 `PuzzleProgress` 维护必需节点集合，忽略未知及重复激活。`PuzzleController` 只负责把双节点结果交给规则层，解锁已有场景宝箱，不直接发放奖励。部分节点在重载后重新点亮；完成记录永久保存。表现与纯节点完成逻辑分离。

## 7. Teleport

玩家必须接近信标并 E 激活。已发现但未激活的点在地图显示为待激活，不允许传送。

传送顺序：验证已激活和生命状态 → 射线确认地面及坡度 → 胶囊检查落点空间及敌人 → 暂停 CharacterController 并移动 → 恢复组件 → 清空攻击/闪避/位移 → 重置敌人遭遇 → 退出建造及菜单 → 保存。失败不改变位置。

## 8. Region discovery / map / layout

三个轻量 Box Trigger 区域：wind-meadow、echo-mesa、split-canyon。原 forest/quarry/ruins/camp 的 `visited` 继续保留。地图显示玩家、已发现 POI、已激活信标、已发现区域和暗色未知区域；支持围绕鼠标缩放 1～3 倍和限界拖动。无需 GPU Fog of War。

| 位置 | 高度/路线与次级目标 |
| --- | --- |
| 据点信标 (8, 4) | 地面；出生即可辨认附近信标和东侧平台地标 |
| 中层平台 (51, -8) | 高 6 米；南侧攀爬捷径，西侧缓坡，行旅匣 (53, -9) |
| 回声台地 (78, 8) | 高 14 米；中层连接长缓坡，高台信标 (77, 8) 与听风尖塔 (84, 14) |
| 风隙峡谷 (81, 32) | 低地 0 米，两岸高 6 米；高台北侧滑翔或绕行步行到达，双石解谜与珍稀回声匣 |
| 星砂矿苑 / 北方守卫 | 接回原矿区和营地路线，不改变原 10 名敌人及星核奖励条件 |

坐标列是世界 X/Z。引导结构：出生看见高处信标 → 缓坡旁行旅匣 → 攀爬捷径/平台 → 高台视点 → 峡谷滑翔 → 共鸣石 → 回声匣 → 原矿区/北方营地。安全长路与体力捷径同时存在。

## 9. Save schema

v2 新增 `discoveredPOIIds / activatedTeleportIds / discoveredRegionIds / openedTreasureIds / completedPuzzleIds`。所有字段按目录和唯一性校验；激活信标必须已发现，解谜箱必须有完成记录。目录之外的状态不自动忽略，避免悄悄丢失数据。

v1 读入内存后升级为 v2 并初始化探索集合；旧背包、建筑、claimed、defeated、visited 保持不变。只有成功保存才改写主档，并留下原档备份。v2 缺少集合或状态非法按损坏处理，尝试备份；未知正版本在主档或备份中出现时都禁止覆盖。原子临时写入、备份恢复、归档行为保留。

## 10. Performance / debug / future expansion

没有新增逐帧 FindObjectsOfType 或 POI Update。兴趣点/区域由 trigger 驱动；交互使用 8 米空间格索引，每次查附近 9 格，仅交互对象数量变化时重建。地图仅打开时创建布局，拖动直接移动 RectTransform。NavMesh 仍只在启动构建一次；未引入 streaming、ECS 或大型框架。

Editor/Development 条件编译提供无限体力、攀爬射线、选中 POI 半径/区域边界、安全信标传送和发现状态重置。调试重置故意保留领奖/已完成解谜记录，避免资源重复领取；完整清零用原有「新旅程」归档机制。

后续需要：复杂网格凸角绕行、攀爬 IK、正式角色动画、地图标签避让、更细分区域边界和手工视线引导；实机完整路线的 CPU/GPU/GC 采样与真人镜头/手感验收。没有实现元素反应、多角色、网络、剧情或大型世界加载。

验证记录见 `Unity实现与验证记录.md`；自动化测试和离屏冒烟不替代真人游玩验收。
