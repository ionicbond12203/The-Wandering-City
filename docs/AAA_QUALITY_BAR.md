# AAA Quality Bar

## 质量等级

等级针对声明的完整范围，不可用某个子系统的测试结果给整个游戏升级。当前整体 **Prototype**，局部切片证据存在；以下更高等级均尚未获得。

| 等级 | 必需证据 | 不足以晋级的情况 |
| --- | --- | --- |
| Prototype | 核心假设可玩；规则和错误路径测试；占位和限制诚实披露；能构建复现 | 允许 placeholder、局部硬编码和已登记技术债；不是最终品质承诺 |
| Vertical Slice | 一条明确既有路线贯通探索/战斗/奖励/存档；代表性正式角色、环境、动画与声音；重复生产该切片的管线；实际试玩、Build 视觉与路线性能验收 | 只有原创程序网格、空配乐槽、自动传送冒烟、短时 FPS，仍不能晋级 |
| Production Candidate | 切片质量可重复；已界定内容规模下的 streaming/state/save/nav/AI 生命周期通过；工具保护手工作品；性能/内存预算、旧档兼容、发布构建与证据归档稳定 | 仅某条路线好看、仅单机一次绿色，或依赖未保存的本机结果 |
| Production Ready | 明确发行范围、硬件矩阵及所有质量门禁通过；无阻断/严重缺陷；真实试玩、长时稳定、升级/回滚/恢复、安装包与许可审查齐全，开发者具名批准发布 | 文档齐全、代码可编译、功能数量多、构建成功都不能单独证明可发行 |

“tests pass” != production quality

“looks better” != visual acceptance

“large map” != open world

“many systems” != AAA quality

## 验收分层

每个 milestone 分别记录 automated / playable / visual / performance / build 状态，使用 Passed、Failed、Blocked、Not run、Not applicable（附理由）。任何必需门禁未通过，则该 milestone 不可标 complete。G00 只治理，无新增视觉/玩法，因此无需伪造新的视觉或真人试玩验收；仍必须完整测试和 Windows Build。

自动测试必须覆盖成功、失败不改状态、重入/幂等、暂停/死亡/卸载和旧存档兼容。不得删除失败测试、过滤回归或用 Ignore/Skip 换绿色。历史测试总数只是历史记录；每次报告本次实际总数、通过、失败和跳过。

实际试玩使用真实 Build、正常输入和隔离 QA 存档，记录操作者、时长、路线、失败点与结论。自动传送/直接击败敌人的辅助模式单列，不能冒称完整自然流程；视觉/音频艺术判断要人工审查，自动像素/音频峰值仅检查技术健康。

## 视觉验收

固定原始 Build 相机视点、角色动作、天气/光照、分辨率、画质及曝光；前景/中景/地平线、材质错误、遮挡、脚底接触、阴影、LOD 跳变、HUD 裁切和文字对比逐项记录。至少包含既有出生点、密林、高点、攀爬/滑翔、战斗与地图。无粉色 shader 是必要条件，不是艺术验收。

原生 framebuffer 与 URP Render Request 分开标记；后者可能改变 Terrain Detail 和 Canvas 渲染，不能替代前台最终呈现。保存未经修改截图、审查备注与失败图；不能以图片生成或后处理伪造游戏证据。发布 UI 需覆盖 1280×720、1366×768、1600×900、1920×1080、2560×1440、2560×1080 及安全区。

## 性能门槛与测量协议

目标方向为 Windows / 1920×1080 / URP PC / 60 FPS（16.67 ms 帧预算）。**最低及推荐硬件尚未批准，当前不存在“已满足”的发行性能结论。** 历史 Ultra 9 285H / Arc 140T 只是测试设备，不自动成为最低配置。

G01 必须先固定硬件、驱动、分辨率、画质、VSync/帧率上限、Build 类型、路线、预热和样本数。建议协议：预热 60 秒，既有探索/高点/密林/战斗/天气路线连续 10 分钟，冷启动和热运行各记录，至少 3 次；报告所有重复结果，不能只挑最快样本。计时采样与截图/PNG 编码分离，前台路线用于体验判断，Profiler 构建用于瓶颈归因。

下列是待 G01 冻结的工程预算提案，不是已测结果；未冻结且未测的项阻止后续性能门禁晋级：

| 指标 | 初始验收提案 |
| --- | --- |
| 全路线 frame time | P95 ≤16.67 ms，P99 ≤25 ms；>50 ms 卡顿逐项归因，不能平均掩盖 |
| CPU / GPU | 分别记录主线程、渲染线程、GPU 和等待；按各自瓶颈验收，不把相加当帧时长 |
| GC | 新增稳态高频路径 0 B/frame；已有分配单列债务；全路线 GC 暂停须纳入帧时间 |
| 内存 | G01 按参考硬件批准 Unity/进程/显存上限；30 次往返卸载后无单调增长；释放后稳定值增幅 ≤5% |
| streaming/nav/AI | 每帧 CPU 总预算、队列延迟、并发数、驻留块数在 G01/G06 场景基线明确；未定数值不可声称可扩展 |
| 回归比较 | 同机同设置三次样本中位数，相关 CPU/GPU/内存指标恶化 >5% 必须分析和批准，不可静默接受 |

必须同时报告帧分位、GC bytes/collections、内存峰值、draw calls/batches、导航请求/构建、模拟实体数量、加载时长与驻留量。计数器不支持、0 个有效样本、历史报告的 -1 均为 unavailable，不能转换成达标。性能改动须有前后 trace 和明确差值；纯治理 G00 不声称性能提升。

## Build、证据与发布

每项完成执行 `game/Tools/Verify.ps1`；需要构建时执行 `game/Tools/Verify.ps1 -Build`，包含完整 EditMode、PlayMode 和 Windows 构建。目前仅生成 Mono x64 Development Build；没有 Release/CI 或长时测试通过的含义。

证据清单包含 UTC 时间、source commit + dirty diff hash（若尚未提交）、最终交付 commit 关联、Unity/Packages、机器/驱动、完整命令、退出码、测试数量、Build 文件 SHA256、原始日志/XML/截图/trace 路径与哈希、捕获方式、人工判定、失败历史和未测项。不能将不同 HEAD 的旧截图归给新构建。

`artifacts/` 和 `game/Builds/` 继续忽略；每次使用唯一 evidence 目录，运行前保存既有报告，失败重跑不覆盖失败证据。在 docs 提交可复现摘要；阶段晋级前必须将完整证据导出到开发者维护的版本化归档（或后续 CI artifact），记录位置、校验和，至少保留当前与前一验收版本以及未解决失败。仅本机短期文件不足以支持多年可追踪；远端归档目前未建立，不能声称已具备。

发布前另需 Release 构建、清洁机器安装/启动/退出、无调试 UI、v1/v2 和未来迁移矩阵、存档故障恢复、2 小时既有路线 soak、许可与 art blocker 关闭，以及已批准硬件矩阵的完整验收。代码回滚和玩家数据回滚分开处理，绝不能强制旧程序覆盖新格式进度。

质量状态的变更由开发者审阅证据并具名记录；Codex 报告真实结果，不能自授 AAA 或 Production Ready。执行顺序见 [路线图](AAA_ROADMAP.md)。
